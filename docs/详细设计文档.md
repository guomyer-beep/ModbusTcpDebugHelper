# ModbusTCP 设备调试助手 — 详细设计文档（Web 版）

> 依据文档：`docs/需求文档.md`
> 版本：V4.0（手写 Modbus TCP 协议栈 + SQLite 内存库日志）
> 用途：指导后续编码实现，覆盖架构、API、类型设计、协议实现、SQLite、前端、异常与测试
> 技术栈：C# / .NET 8 / ASP.NET Core Web API（Controller 风格）/ 手写 Modbus TCP / Microsoft.Data.Sqlite（内存库）/ 原生 HTML+JS+CSS

---

## 1. 设计概述

### 1.1 设计目标

1. 把原控制台交互功能全部封装为 REST API，前端通过按钮调用，实现「连接 / 读取 / 写入 / 断开 / 查日志」。
2. 保留核心亮点「原始 Modbus 报文打印」——手写协议栈，发送/接收到的字节即真实报文。
3. 用 SQLite（内存库）统一存储三类日志。
4. 异常全捕获，任何操作不崩溃，返回结构化 JSON + 中文提示。
5. 采用 **Controller Web API**（类 Spring MVC 的分层风格）。

### 1.2 设计原则

- **分层解耦**：前端层（静态页 + fetch）→ API 层（Controller）→ 业务层（Service）→ 协议层（手写 Modbus TCP）。
- **单一职责**：`ModbusClientService` 唯一持有 TCP 连接；`LogStore` 唯一持有 SQLite 连接。
- **单例连接**：Modbus 长连接与 SQLite 内存库都用单例生命周期，跨 HTTP 请求共享。
- **线程安全**：`SemaphoreSlim` 串行化读写；SQLite 用 `lock` 串行化访问。
- **先简单、可演进**：日志先落内存库，切换文件只改连接串。

### 5.2 状态码约定

| HTTP 状态码 | 场景 |
|---|---|
| 200 | 正常执行，业务成败看 `success` |
| 400 | 请求体缺失 / 参数非法 |
| 500 | 未预期异常（全局中间件兜底） |

> 业务失败（未连接、从站异常、网络错误）统一 200 + `success=false` + 中文 message，前端处理最简洁。

## 6. 业务层设计

### 6.1 ModbusClientService（单例，核心，手写协议）

```csharp
public sealed class ModbusClientService : IDisposable
{
    private const byte UnitId = 1;             // 从站单元标识
    private const int ConnectTimeoutMs = 3000; // 连接超时
    private const int TimeoutMs = 3000;        // 读写超时

    private readonly SemaphoreSlim _gate = new(1, 1); // 串行化连接/读写
    private readonly LogStore _log;
    private TcpClient? _tcp;
    private NetworkStream? _stream;
    private bool _connected;
    private ushort _transactionId = 1;

    public bool IsConnected => _connected && _tcp is { Connected: true };
    public string? Host { get; private set; }
    public int? Port { get; private set; }

    public OperationResult Connect(string host, int port);
    public OperationResult Disconnect();
    public StatusDto GetStatus();
    public OperationResult ReadHolding(ushort startAddress, ushort quantity); // 0 起始
    public OperationResult WriteHolding(ushort address, ushort value);        // 0 起始
    public void Dispose();
}
```

**设计要点：**

1. **线程安全**：方法内 `_gate.Wait()` + `finally` 释放，防止并发访问同一 `TcpClient`。
2. **未连接防线**：读/写前置检查 `IsConnected`，否则返回 `{ Success=false, Message="请先连接设备" }`。
3. **连接超时**：`tcp.ConnectAsync(host, port, cts.Token)` + `CancellationTokenSource(3s)`，取消抛 `OperationCanceledException` → 映射「连接超时」。
4. **真实报文链路**：请求帧自己 `BuildRequest` 构造、响应帧 `ReadFrame` 读回 → `ToHex` 转字符串 →（a）写回 `RawRequestHex/RawResponseHex`（b）`_log.LogPacket(...)` 落库（c）`_log.LogRegister(...)`。
5. **地址约定**：对外接口用 0 起始协议地址；Controller 负责把「1 起始地址」`-1` 后传入；读结果返回时 `+1` 回 1 起始展示。
6. **事务 ID**：`_transactionId` 自增，请求/响应一至，跳过 0。

### 6.2 LogStore（单例，SQLite 内存库）

```csharp
public sealed class LogStore : IDisposable
{
    private readonly SqliteConnection _conn;
    private readonly object _sync = new();

    public LogStore(IConfiguration config)
    {
        string cs = config["LogStore:ConnectionString"] ?? "Data Source=:memory:";
        _conn = new SqliteConnection(cs);
        _conn.Open();     // 常开：内存库数据随连接存活（进程内共享）
        InitSchema();
    }

    public void LogPacket(string direction, string label, string hex);
    public void LogConnection(string host, int port, string result);
    public void LogRegister(string direction, ushort address, int? value, int quantity);

    public List<PacketLogEntry>     GetPackets(int count);
    public List<RegisterLogEntry>   GetRegisters(int count);
    public List<ConnectionLogEntry> GetConnections(int count);
    public void ClearPackets();
    public void Dispose();  // _conn.Dispose()
}
```

**关键要点：**

1. **常开连接是硬要求**：SQLite `:memory:` 每个连接一个独立库，连接关闭数据即丢。`LogStore` 单例在构造时 `Open()` 后持有，直到应用关闭。
2. **线程安全**：单个 `SqliteConnection` 并发操作会报错，所有 DB 操作包 `lock(_sync)`。
3. **切文件**：连接串换成 `Data Source=modbus.db`（`appsettings.json` 的 `LogStore:ConnectionString`），代码零改动。

## 7. SQLite 日志存储设计

### 7.1 表结构（DDL）

```sql
CREATE TABLE IF NOT EXISTS packet_log (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    ts        TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
    direction TEXT    NOT NULL,          -- 'TX' / 'RX'
    label     TEXT    NOT NULL,          -- 如 '读保持寄存器'
    hex       TEXT    NOT NULL
);

CREATE TABLE IF NOT EXISTS connection_log (
    id     INTEGER PRIMARY KEY AUTOINCREMENT,
    ts     TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
    host   TEXT    NOT NULL,
    port   INTEGER NOT NULL,
    result TEXT    NOT NULL              -- 'success' / 'fail:...'
);

CREATE TABLE IF NOT EXISTS register_log (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    ts        TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
    direction TEXT    NOT NULL,          -- 'read' / 'write'
    address   INTEGER NOT NULL,          -- 0 起始协议地址
    value     INTEGER,                   -- 读为 NULL，写为写入值
    quantity  INTEGER DEFAULT 1
);
```

### 7.2 查询语句约定

- 列表一律 `ORDER BY id DESC LIMIT @count`（最新在前），避免依赖时间字符串排序。
- 参数化 SQL（`@count`、`@host` 等）防注入、省转义。

### 7.3 写日志时机

| 事件 | 落库 |
|---|---|
| 连接成功/失败 | `connection_log` 一条 |
| 读保持寄存器成功 | `register_log`（direction=read, address=起始, value=NULL, quantity=N）+ `packet_log` TX/RX 各一条 |
| 写单寄存器成功 | `register_log`（direction=write, address, value）+ `packet_log` TX/RX 各一条 |

> 失败操作仅写 connection_log（连接类）；寄存器/报文日志只在操作成功时记，避免日志冗杂。

## 9. 协议实现：帧构建与原始报文（核心亮点）

> 手写协议栈意味着不需要「拦截/抓包」——请求帧是**自己构造**的，响应帧是**自己读回**的，因此 `ToHex` 打印的字节天然真实。

### 9.1 帧构建（BuildRequest）

```csharp
// MBAP 头(7) + 功能码(1) + 数据
private static byte[] BuildRequest(ushort transId, byte func, byte[] a, byte[] b)
{
    var frame = new byte[7 + 1 + a.Length + b.Length];
    U16(transId).CopyTo(frame, 0);                            // 事务 ID
    frame[2] = 0; frame[3] = 0;                               // 协议 ID = 0x0000
    U16((ushort)(1 + 1 + a.Length + b.Length)).CopyTo(frame, 4); // 长度 = 单元+功能+数据
    frame[6] = UnitId;                                        // 单元 ID
    frame[7] = func;                                          // 功能码
    a.CopyTo(frame, 8);
    b.CopyTo(frame, 8 + a.Length);
    return frame;
}
```

- 读 FC03：`BuildRequest(transId, 0x03, U16(start), U16(qty))` → 12 字节。
- 写 FC06：`BuildRequest(transId, 0x06, U16(addr), U16(value))` → 12 字节。

### 9.2 帧读取（ReadFrame + ReadExact）

```csharp
private static byte[] ReadFrame(NetworkStream stream)
{
    var mbap = new byte[7];
    ReadExact(stream, mbap, 0, 7);              // 固定读 7 字节 MBAP 头
    int length = (mbap[4] << 8) | mbap[5];      // 单元 ID + PDU 字节数
    int pduLen = length - 1;
    var pdu = new byte[pduLen];
    ReadExact(stream, pdu, 0, pduLen);          // 读 PDU
    // 拼成完整帧返回（供 ToHex 打印）
}

// NetworkStream.Read 可能返回部分字节，循环读满
private static void ReadExact(NetworkStream stream, byte[] buffer, int offset, int count);
```

### 9.3 帧解析与异常码映射

```csharp
private static ushort[] ParseReadResponse(byte[] frame, ushort expectedQty)
{
    byte func = frame[7];
    if (func == 0x83) throw new ModbusFrameException(MapErrorCode(frame[8])); // 异常响应
    // func == 0x03：校验字节数 == qty*2，逐寄存器解析（大端）
}

private static string MapErrorCode(byte code) => code switch
{
    0x01 => "非法功能", 0x02 => "非法数据地址", 0x03 => "非法数据值", 0x04 => "从站设备故障", ...
};
```

## 10. Modbus 报文格式（打印依据）

### 10.1 Modbus TCP ADU

| 字段 | 字节 | 说明 |
|---|---|---|
| Transaction ID | 2 | 大端，请求/响应一致 |
| Protocol ID | 2 | 0x0000 |
| Length | 2 | Unit ID + PDU 字节数 |
| Unit ID | 1 | 0x01 |
| PDU | N | 功能码 + 数据 |

### 10.2 FC03 / FC06 / 异常

- 读请求 PDU：`03 | 起始地址(2) | 数量(2)`；响应：`03 | 字节数(1) | 值序列`。
- 写请求/响应 PDU：`06 | 地址(2) | 值(2)`（响应回显请求）。
- 异常响应：功能码 + 0x80（如 0x83 / 0x86）+ 异常码（`0x01` 非法功能、`0x02` 非法地址、`0x03` 非法值、`0x04` 从站故障）。

## 11. 异常处理与映射

| 异常 | 场景 | 返回 message |
|---|---|---|
| `SocketException: ConnectionRefused` | 端口无监听 | `连接被拒绝：请检查 IP/端口或确认从站已启动` |
| `OperationCanceledException`（连接） | 连接超时（CTS 3s） | `连接超时，目标不可达` |
| `IOException`（读写） | 读写超时 / 连接被关闭 | `通信中断或连接已关闭，请重新连接` |
| `ModbusFrameException` | 从站返回异常码 / 响应非法 | `从站异常码 0x??（非法地址/非法值/从站故障）` |
| 其它 `Exception` | 兜底 | `操作失败：{msg}` |

**实现位置**：Service 层 catch 转 `OperationResult`；Controller 层参数校验 400；全局异常中间件兜底 500。

## 13. 关键设计决策

| # | 决策 | 立场 | 说明 |
|---|---|---|---|
| 1 | 协议实现方式 | 手写 Modbus TCP，不依赖第三方库 | 报文天然真实、可审计 |
| 2 | 连接超时 | `ConnectAsync` + `CancellationTokenSource(3s)` | 避免 OS 默认 ~21s 卡死 |
| 3 | SQLite 内存库跨请求共享 | 单例 + 常开连接 | 内存库随连接存活 |
| 4 | SQLite 线程安全 | `lock` 串行化 | 单连接并发会报错 |
| 5 | Modbus 连接并发控制 | `SemaphoreSlim` 串行化 | 防并发写同一 TcpClient |
| 6 | 业务失败 HTTP 状态 | 统一 200 + `success=false` | 前端处理简洁 |
| 7 | 寄存器地址 0/1 起始 | 前端 1 起始，Controller `-1` 转 0 | 展示 1 起始，协议 0 起始 |
| 8 | 日志时间存储 | 存 `datetime('now','localtime')` 字符串，按 id 倒序 | 避免时区解析 |
