# ModbusTCP 设备调试助手 — 需求文档

> 项目类型：个人兴趣 Demo，C# .NET 8 Web 应用（ASP.NET Core Web API + 原生 HTML/JS/CSS 前端）
> 开发 IDE：JetBrains Rider（工程兼容 Visual Studio 2022）
> 开发方式：AI 辅助编码，人工完成逻辑校验、异常处理、测试调优
> 测试环境：Modbus Slave（Modbus 仿真从站软件）

---

## 1. 项目概述

### 1.1 项目背景

机械/工控行业现场，IoT 网关常通过 RS485 总线、使用 Modbus RTU 协议采集电表、设备控制器等仪表数据；网关再将 Modbus RTU 转为 Modbus TCP 对外提供访问。现场调试人员需要简易工具快速验证 Modbus 通信链路、读取/修改仪表寄存器、排查通信故障。市面上商用 Modbus 调试软件体积大、功能繁杂。

本项目自研轻量 **Web 版 ModbusTCP 主站调试工具**：后端提供 REST API 封装 Modbus 读写能力，前端网页提供直观操作界面，实现寄存器读写、原始报文打印与日志查询，用于学习与验证 Modbus 主从通信原理。

### 1.2 项目目标

1. 实现 Modbus TCP 客户端（主站）基础通信能力，可连接 Modbus 仿真从站或工业网关。
2. 封装 REST API（连接 / 断开 / 读 / 写 / 状态 / 日志），前端页面通过按钮调用。
3. 前端展示寄存器读写结果与**原始收发 Modbus 报文**，辅助定位通信故障（核心亮点）。
4. 用 SQLite 存储报文/连接/寄存器日志，支撑「查看日志」功能。
5. 完善异常捕获，网络断开、超时、非法地址等场景给出友好中文提示，程序不崩溃。
6. 代码结构清晰（前后端分离、Controller/Service 分层）、注释完整，上传 GitHub，附 README 与运行截图。

## 2. 功能需求

### 2.1 主界面

浏览器打开 `http://localhost:8080`，展示功能页，包含四个操作区：

- ① 连接设备区（IP、端口输入 + 连接/断开按钮）
- ② 读保持寄存器区（起始地址、数量输入 + 读取按钮 + 结果表格）
- ③ 写单寄存器区（地址、数值输入 + 写入按钮）
- ④ 日志展示区（本次收发报文 + 历史报文日志）

### 2.2 功能 1：连接 Modbus TCP 从站

1. 输入目标 IP 地址、端口号（默认 502），点击【连接】。
2. 前端调用 `POST /api/modbus/connect`，后端尝试建立 Modbus TCP 连接。
3. 成功：状态徽标变「已连接」，保存连接对象；同时写一条 `connection_log` 记录。
4. 失败：返回结构化 JSON（`success=false` + 中文原因），前端提示条展示。

### 2.3 功能 2：读取保持寄存器（功能码 03）

1. 前置校验：未连接时后端返回「请先连接设备」。
2. 输入寄存器起始地址（1 起始）、读取数量，点击【读取】。
3. 后端手写 Modbus TCP 读取保持寄存器，返回寄存器数值列表；写 `register_log` 记录。
4. 前端展示结果表格 + ✨【亮点】本次**原始请求/响应报文**（十六进制）；报文同步写入 `packet_log`。
5. 异常（通信中断、非法地址、从站异常响应）返回中文提示。

### 2.4 功能 3：写入保持寄存器（功能码 06）

1. 前置校验：必须已建立连接。
2. 输入寄存器地址（1 起始）、待写数值（0~65535），点击【写入】。
3. 后端执行写单寄存器，写 `register_log` 记录；前端提示成功并展示本次收发原始报文。
4. 异常捕获并友好提示。

> 简化：只做单寄存器写入，不做多寄存器批量写入。

### 2.5 功能 4：断开设备连接

1. 点击【断开】，调用 `POST /api/modbus/disconnect`。
2. 后端释放 TCP 资源，前端状态徽标变「未连接」。

### 2.6 功能 5：查看日志

1. 前端调用查询接口获取历史日志：报文（`GET /api/logs/packets`）、寄存器（`GET /api/logs/registers`）、连接（`GET /api/logs/connections`）。
2. 报文日志按时间倒序展示，TX/RX 用不同颜色区分；支持【刷新】【清空】。

### 2.7 全局异常处理

所有通信/协议操作 try-catch：
- 网络超时、网络断开
- 从站返回异常码（Modbus Exception）
- 请求参数非法、超出范围
- 资源释放异常

统一返回结构化 JSON + 中文提示，程序不崩溃；未预期异常由全局异常中间件兜底（HTTP 500）。

### 2.8 输入校验

IP、端口、寄存器地址、值、数量：
- 校验是否合法数字、是否在取值范围
- 非法输入返回 400 + 中文提示，前端不发起协议调用

### 2.9 SQLite 日志存储（内存库）

> 用 `Microsoft.Data.Sqlite` 记录日志。**当前先写入内存数据库**（`Data Source=:memory:`，临时、重启即清空），简单省事；后续要持久化只需把连接串换成文件路径，其余代码不变。

- 建三张表：`packet_log`（收发报文）、`connection_log`（连接历史）、`register_log`（寄存器读写日志）。
- 连接、读写、收发报文时写入对应记录。
- 提供日志查询接口（见 §2.6）。
- 体现知识点：建表、插入、查询（`SELECT ... ORDER BY ... LIMIT`）。
- 技术要点：内存库需**单例 + 常开连接**，否则数据随连接关闭而丢失（详见《详细设计文档》§7）。

## 3. 非功能需求

1. **开发环境**：.NET 8 Web 项目；Rider 开发，兼容 VS 2022。
2. **技术栈**：ASP.NET Core Web API（Controller 风格）+ 原生 HTML/JS/CSS + 手写 Modbus TCP 协议栈。
3. **第三方依赖**：NuGet 包 Microsoft.Data.Sqlite。
4. **代码规范**：中文注释、命名规范、Controller/Service/DTO 分层清晰。
5. **日志输出**：报文十六进制格式，前端可读、可复制。
6. **稳定性**：重复读写无内存泄漏、无资源未释放；并发点击不崩溃（`SemaphoreSlim` + DB `lock` 串行化）。
7. **可演示性**：本地 Modbus Slave 一键跑通，有运行截图用于 GitHub 文档。

## 4. 范围界定（边界）

### 4.1 ✅ 在本项目内
- Modbus TCP 主站通信
- 保持寄存器读、写（工业仪表最常用）
- REST API + Web 前端交互
- 原始报文打印、异常捕获、连接管理
- SQLite 日志存储（内存库）
- 使用 Modbus Slave 仿真软件完成功能验证

### 4.2 ❌ 不在本项目内（减少工作量）
- 不做复杂前端框架/权限登录（纯个人 Demo）
- 不实现线圈、离散输入等其他功能码（聚焦保持寄存器）
- 不开发 Modbus 从站，仅主站客户端

### 4.3 串口（RS232/RS485）的处理策略

本项目为控制体量与降低复杂度，**不直接实现底层串口（RS232/RS485）**。策略：

- 现场 RS485 仪表 → IoT 网关 → Modbus TCP 的链路体现了「RS485 → 网关 → TCP」的典型采集场景。
- 如需直连 RS485，后续可增加串口模块（当前 Demo 优先保证 TCP 稳定可用）。

## 5. 测试需求

### 5.1 测试环境
- Modbus Slave 仿真软件，本机开启 Modbus TCP 服务，默认端口 502。
- 在仿真软件预先设置保持寄存器初始值，用于读写验证。
- 浏览器访问 `http://localhost:8080`。

### 5.2 测试用例
1. 连接测试：正确 IP:502 → 连接成功；错误 IP/端口 → 提示连接失败。
2. 读寄存器：读取预设寄存器，返回值与仿真一致；打印原始报文。
3. 写寄存器：写入数值，Modbus Slave 界面同步更新；打印原始报文。
4. 异常场景：未连接直接读写 → 提示先连接；地址非法 → 捕获 Modbus 异常。
5. 日志查询：连续读写后，报文/寄存器/连接日志正确展示。
6. 断连测试：断开后状态徽标更新，资源释放。
7. 数据生命周期：进程重启后内存库日志清空（符合「临时」预期）。
